Closures, callables and generators

Closures are how a framework lets you hand it behaviour instead of data: every route definition, every event listener, every collection pipeline is one. Generators are the answer to the question "how do I process a 2 GB CSV on a 512 MB container". Neither appears in an advert, and both come up the moment somebody looks at your code.

From the advert

Not in any advert. No posting names closures — but every framework you will touch is built on them, and generators are the difference between an import job that works and one that dies at row 40 000 with an exhausted memory limit.

use() copies, unless you say otherwise

🧒 Simple

A closure is a function that took a photograph of some variables when it was created. It can look at the photograph later, even somewhere else entirely. use ($x) is the photograph; use (&$x) is a live window onto the real thing.

🎓 Professional

use ($x) binds by value at the moment the closure is defined, not when it is called. use (&$x) binds by reference, so the closure sees later changes and its own writes escape.

Arrow functions (fn () => ..., PHP 7.4) capture the entire enclosing scope automatically and always by value. That is the trade: they are shorter, they are limited to a single expression, and there is no way to capture by reference. For a usort comparator or an array_map callback that is exactly right.

⚠ Trap

The classic: building closures in a loop and expecting each to remember its own iteration. With use ($i) each closure keeps its own copy and it works; with use (&$i) every closure shares one variable, and after the loop they all see the final value. The by-reference version is the one people write when they are pattern-matching from another language, and the bug it produces looks like the framework is broken. 

<?php
$byValue = []; $byRef = [];
for ($i = 0; $i < 3; $i++) {
    $byValue[] = function () use ($i)      { return $i; };
    $byRef[]   = function () use (&$i)     { return $i; };
}
echo $byValue[0](), $byValue[1](), $byValue[2](), PHP_EOL;  // 012
echo $byRef[0](),   $byRef[1](),   $byRef[2](),   PHP_EOL;  // 333

$this, bindTo and why a Laravel route closure can see the app

🧒 Simple

A closure written inside a class quietly carries that object with it, so it can still say $this. You can also take a closure and re-attach it to a different object, which is the trick that makes a lot of framework magic possible.

🎓 Professional

A Closure created in an object context automatically binds $this and a scope. Closure::bind() / ->bindTo() rebinds both; passing a scope grants access to private and protected members of that class, which is how test helpers and macro systems reach inside objects.

Closure::fromCallable() and, since 8.1, the first-class callable syntax $obj->method(...) turn a method into a real Closure. Prefer it over the string and array callable forms — 'strlen' and [$obj, 'method'] are not checked until they are invoked, while strlen(...) fails at the point you wrote the mistake and is understood by static analysis (ch. 27).

Try it. The second half is how a framework "opens" an object it does not own. Use it to understand your framework; think twice before shipping it in your own code.

<?php declare(strict_types=1);

final class Basket
{
    private array $lines = ['espresso' => 120, 'cornetto' => 150];

    public function totalWith(callable $discount): int
    {
        // First-class callable syntax: array_sum(...) is a real Closure.
        return $discount(array_sum($this->lines));
    }
}

$tenPercent = fn (int $cents): int => (int) round($cents * 0.9);
echo (new Basket)->totalWith($tenPercent), PHP_EOL;   // 243

// Rebinding: a closure given the Basket scope can read a private property.
$peek = function () { return array_keys($this->lines); };
$bound = Closure::bind($peek, new Basket, Basket::class);
print_r($bound());                                     // [espresso, cornetto]

Generators: yield, and the memory argument

🧒 Simple

A normal function builds the whole list and hands it over. A generator hands you one item, then pauses exactly where it was until you ask for the next. You can walk a file of ten million rows holding one row in memory at a time.

🎓 Professional

Any function containing yield returns a Generator — an Iterator that suspends and resumes, keeping its local state between calls. Memory is O(1) in the number of items rather than O(n), so the ceiling on an import becomes disk and time instead of memory_limit.

Two things to have ready. yield from delegates to another iterable, which is how you compose pipelines without flattening them into an array. And a generator is forward-only and single-use: no count(), no array access, and it cannot be rewound once started — iterator_to_array() exists but throws away the entire benefit, so reaching for it is the sign that you wanted an array all along.

Try it. Generate a large CSV first (php -r 'for($i=0;$i<500000;$i++) echo "ORD-$i,1999\n";' > big.csv), then run both halves and watch the peak-memory line. This is the chapter’s whole argument in two numbers.

<?php declare(strict_types=1);

/** Lazy: one line resident at a time. */
function rows(string $path): Generator
{
    $fh = fopen($path, 'rb');
    try {
        while (($line = fgetcsv($fh)) !== false) {
            yield $line;
        }
    } finally {
        fclose($fh);          // finally runs even if the consumer breaks early
    }
}

$total = 0;
foreach (rows('big.csv') as [$ref, $cents]) {
    $total += (int) $cents;
}
printf("lazy   total=%d peak=%.1f MB%s", $total, memory_get_peak_usage(true) / 1048576, PHP_EOL);

// The eager version, for contrast — same result, the whole file resident:
//   $all = array_map('str_getcsv', file('big.csv'));
⚠ Trap

A generator that opens a file or a database cursor must clean up in a finally. If the consumer breaks out of the foreach, the generator is never resumed to its natural end — the code after the loop inside the function simply does not run. Put fclose() in finally and it is released when the generator is destroyed. This is the leak that only shows up in the job that stops early on an error.

Where you will actually meet these

🧒 Simple

You are already using both, probably without noticing: the function you pass to a route, the one inside map or filter, and the "chunk" helpers that walk a big table without loading it.

🎓 Professional
  • Routing and events. Route::get('/orders', fn () => ...) and every listener is a closure the framework stores and invokes later — which is why closures in Laravel routes break route:cache: a closure cannot be serialised.
  • Collections. array_map, array_filter, usort (ch. 06) take callables; arrow functions made them readable.
  • Eloquent’s cursor() returns a LazyCollection backed by a generator, and chunkById() is the same idea done in query pages. Use them on any table you do not personally know the size of.
  • Fibers (8.1) are the generalisation — a full suspendable call stack rather than one function — and they are plumbing for async libraries, not something you write directly (ch. 07).
Golden rules
  • use ($x) copies at definition time. Capture by reference only when you mean to share.
  • Arrow functions capture everything, by value, one expression. That is the whole contract.
  • Prefer $obj->method(...) over string and array callables — it fails where you wrote it.
  • If it does not fit in memory, yield it. O(1) instead of O(n).
  • Generators clean up in finally, because the consumer may break early.
  • A generator is single-use and uncountable. Wanting count() means you wanted an array.

"Come importerebbe un CSV da due gigabyte?"

The interviewer is testing whether you reach for memory or for laziness: "Non lo carico in memoria. Uso un generator che fa fgetcsv riga per riga e yield, così la memoria resta costante; inserisco a batch di qualche migliaio dentro una transazione invece di una query per riga, e chiudo il file in un finally perché se il consumer si ferma prima il generator non arriva mai in fondo. Se l’import è parte di una richiesta web, lo sposto su una coda: trenta secondi di max_execution_time non sono negoziabili." Batching and the queue are what turn a correct answer into an experienced one.
