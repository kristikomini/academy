Integrations: webhooks, SOAP, CSV and XML

Consuming somebody else's API is a different discipline from building one, because you control none of it. It will be slow, it will return 200 with an error inside, it will send you the same webhook twice, and the corriere's endpoint will still be SOAP. This chapter is the defensive posture that turns those from incidents into log lines.

From the advert

"Integrazione con sistemi e servizi di terze parti". In this market that means a courier, a payment provider, an ERP, and the SDI (ch. 33). At least one of them will speak SOAP, and at least one will send you a CSV over FTP and call it an API.

Outbound calls: timeouts, retries and backoff

🧒 Simple

When you call someone else's server you are lending them your worker. If they take forty seconds, you took forty seconds. Always say how long you are willing to wait, and always decide in advance what you will do when the answer is "no".

🎓 Professional

Two timeouts, both set, always. connect_timeout for establishing the connection (small — 2 to 5 seconds) and timeout for the whole request. A Guzzle client with no timeout waits forever by default, and under PHP-FPM that is a worker removed from the pool (ch. 01). Enough of those and the site is down because of somebody else’s outage.

Retry only what is safe to retry. Idempotent methods (GET, PUT, DELETE) and explicitly idempotent POSTs. Retry on connection errors, 429 and 5xx; never on 4xx, which will fail identically forever. Use exponential backoff with jitter — fixed delays synchronise every client into a thundering herd against a service that is already struggling. Respect Retry-After when it is sent, because it is the server telling you the answer.

Circuit breaker for a dependency that fails repeatedly: after N failures, stop calling for a cooling-off period and fail fast. Worth naming in an interview; a Redis counter with a TTL is a perfectly respectable implementation.

⚠ Trap

Retrying a non-idempotent POST is how a customer gets charged twice. The first attempt succeeded at the far end and the response was lost on the way back — your code cannot tell that apart from "it never arrived". Either the endpoint supports an idempotency key, or a retry is a business decision and not a technical one. When you are building the API (ch. 14), accepting an Idempotency-Key header is the gift you give your integrators.

Try it. The retry loop worth having in your head. Note what is not retried, and the jitter.

<?php declare(strict_types=1);

use GuzzleHttp\Client;
use GuzzleHttp\Exception\ConnectException;
use GuzzleHttp\Exception\RequestException;

$http = new Client([
    'connect_timeout' => 3,     // both, always
    'timeout'         => 10,
    'http_errors'     => true,
]);

function callWithRetry(Client $http, string $url, int $attempts = 4): string
{
    for ($try = 1; ; $try++) {
        try {
            return (string) $http->get($url)->getBody();
        } catch (RequestException $e) {
            $status = $e->getResponse()?->getStatusCode();

            // 4xx other than 429 will fail the same way forever. Do not retry.
            if ($status !== null && $status < 500 && $status !== 429) {
                throw $e;
            }
            if ($try >= $attempts) { throw $e; }
        } catch (ConnectException $e) {
            if ($try >= $attempts) { throw $e; }
        }

        // Exponential backoff with jitter: 1s, 2s, 4s ± up to 250ms.
        $sleep = (2 ** ($try - 1)) * 1_000_000 + random_int(0, 250_000);
        usleep($sleep);
    }
}

Webhooks: verify, deduplicate, answer fast

🧒 Simple

A webhook is them calling you instead of you calling them. Three rules: check it really is them, expect the same message more than once, and reply immediately — do the actual work afterwards.

🎓 Professional

Verify the signature before parsing anything. Providers sign the raw body with a shared secret; compute the HMAC over the raw bytes (once you have decoded and re-encoded the JSON, the bytes differ and the signature will never match) and compare with hash_equals(), never ===, to avoid a timing side channel. A signature that includes a timestamp also needs a freshness window, or a captured request can be replayed a year later.

Assume at-least-once delivery. Every serious provider retries when it does not get a 2xx quickly, so duplicates are normal, not exceptional. Store the provider’s event id in a table with a unique constraint and let the database reject the second copy — a SELECT-then-INSERT check has a race that two simultaneous retries will find (ch. 11).

Answer in milliseconds. Persist the raw payload, return 200, and process on a queue (ch. 22). Doing the work inline means their timeout fires, they retry, and now you are processing the same event twice concurrently. Keeping the raw body also means you can replay everything when you find a bug in your handler — which you will.

And return the right status: 200 for accepted, 401 for a bad signature, 4xx for something you will never accept. A 500 on a payload you cannot handle asks them to retry it forever.

SOAP and XML, which you cannot avoid here

🧒 Simple

Before JSON, systems talked in XML with a strict envelope called SOAP. Italian public administration, couriers and older ERPs still do. It is verbose but it is not hard, and PHP has a client built in.

🎓 Professional

ext-soap gives you SoapClient, which reads the WSDL and exposes operations as methods. Practical notes: cache the WSDL in production (soap.wsdl_cache_enabled) because fetching and parsing it on every request is a real cost; set 'exceptions' => true and catch SoapFault; and use __getLastRequest()/__getLastResponse() with 'trace' => true, because debugging SOAP without seeing the envelope is guesswork.

For XML you parse yourself: SimpleXML for small friendly documents, DOMDocument with DOMXPath when there are namespaces — and fatturaPA has namespaces (ch. 33). XMLReader is the streaming parser for files too large to hold, the XML equivalent of a generator (ch. 04).

⚠ Trap

XXE. An XML document can declare an external entity that reads /etc/passwd or makes the server fetch an internal URL — a file disclosure and an SSRF in one. Modern libxml disables external entity loading by default, but any codebase that ever called libxml_disable_entity_loader(false), or runs on an old build, is exposed. Parse untrusted XML with LIBXML_NONET and without LIBXML_NOENT, and treat "we accept XML uploads" as a thing to check on day one (ch. 15).

CSV over FTP, and other 2004 integrations

🧒 Simple

A lot of real integration is still a file dropped on a server every night. It works, it is not beneath you, and the failure modes are entirely predictable — so handle them on purpose.

🎓 Professional

The failure modes, in the order they will happen:

  • Encoding. The file is Windows-1252 or Latin-1, not UTF-8, and the first accented supplier name breaks your import. Detect or agree the encoding and convert on the way in; a utf8mb4 column will reject the invalid bytes outright (ch. 09).
  • Partial files. You read the file while it is still being uploaded. Require an atomic rename, or a .done marker written after the data — never process a file that is still growing.
  • Idempotency again. The same file will be delivered twice. Hash the contents, record what you processed, and skip a repeat.
  • Decimal separators. 1.234,56 is one thousand two hundred, not one point two. This is Italy; assume the comma.
  • Line endings and BOM. A UTF-8 BOM makes your first column header "\u{FEFF}codice", which is why the first column of an import is mysteriously always empty.
  • Stream it with fgetcsv, batch the inserts inside a transaction, and log a per-row error report the client can read — "it failed" is not an acceptable outcome for a nightly job.
Golden rules
  • Two timeouts on every outbound call. No timeout is an outage waiting for someone else's.
  • Retry 429 and 5xx with backoff and jitter; never retry a 4xx.
  • A retried POST needs an idempotency key, or it is a business decision.
  • Verify webhook signatures over the raw body with hash_equals().
  • Webhooks are at-least-once. Unique constraint on the event id; let the database win the race.
  • Store the payload, answer 200, work on the queue. Replayability comes free.
  • Untrusted XML is an XXE risk. No external entities, no network.
  • CSV means encoding, partial files and the comma decimal. All three, every time.

"Come gestirebbe un webhook di pagamento?"

The interviewer is listening for signature, idempotency and queue — in that order: "Prima verifico la firma HMAC sul corpo grezzo, con hash_equals, e controllo il timestamp per evitare replay. Poi salvo il payload così com’è con l’id evento del provider su una colonna unique: se arriva due volte — e arriva due volte, la consegna è at-least-once — il database rifiuta il duplicato e io non processo niente. Rispondo 200 subito e faccio il lavoro vero su una coda, altrimenti scatta il loro timeout e ricevo lo stesso evento in parallelo. Avere il payload salvato mi permette anche di rigiocare tutto quando trovo un bug nel handler."
