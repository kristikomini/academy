Fundamentals: types, juggling, strings, arrays

PHP's type system is the thing that gets it mocked, and the thing interviewers use to find out whether you actually know the language or have only used a framework. Almost all of it comes down to one design decision — values convert themselves to fit the operation — and to the two-character escape hatch from it.

From the advert

"Consolidata esperienza nello sviluppo PHP". This is where "consolidata" is tested. Anyone can write a controller; the questions in this chapter separate people who have debugged PHP from people who have configured it.

Type juggling, and the PHP 8 change

🧒 Simple

PHP tries to be helpful. If you ask it to compare a number with some text, it quietly converts one of them so the comparison can happen at all. Being helpful is fine until it guesses wrong, and then your login form lets the wrong person in.

🎓 Professional

Loose comparison (==) coerces operands to a common type before comparing. PHP 8 changed the rule for the dangerous case: comparing a number to a non-numeric string now casts the number to string, instead of the string to a number.

So 0 == "foo" was true in PHP 7 and is false in PHP 8. Two numeric strings are still compared numerically, which is why "1e2" == "100" remains true. This is the single most-cited PHP 8 breaking change and it comes up constantly in interviews.

⚠ Trap

The historically catastrophic version of this was md5($a) == $b. Some hashes start 0e followed by digits, which PHP read as scientific notation, so two different passwords could both juggle to 0 and compare equal — a "magic hash" authentication bypass. Use ===, or hash_equals() for anything security-sensitive.

Try it. Run this on PHP 8 and then, if you can, on a PHP 7 container. The first line changes.

<?php
var_dump(0 == "foo");        // PHP 8: false   |  PHP 7: true
var_dump("1e2" == "100");    // true — both numeric strings
var_dump("abc" == 0);        // PHP 8: false
var_dump(null == false);     // true
var_dump([] == false);       // true
var_dump("0" == false);      // true
var_dump("" == null);        // true
var_dump(0 === "0");         // false — different types, always

declare(strict_types=1)

🧒 Simple

This line tells PHP: stop being helpful. If a function wants an integer and I hand it the text "5", shout at me instead of quietly converting it.

🎓 Professional

declare(strict_types=1) must be the first statement in the file, and it is per file — it governs the coercion of arguments and return values for calls originating in that file, not calls into it. That per-call-site behaviour is exactly why it has to be declared in every file rather than once somewhere central.

It does not change explicit casts, string interpolation, or internal comparisons. It is a boundary check on function calls, nothing more — and that is enough to catch most of the bugs juggling causes.

Strings, quotes and the null-safe operators

🧒 Simple

Single quotes print exactly what you typed. Double quotes look inside the text for $names and swap in their values.

And ?? means “use this other thing if the first one is missing” — without complaining that it was missing.

🎓 Professional

Single quotes are literal; double quotes interpolate variables and parse escape sequences. Prefer single quotes when you are not interpolating — not for speed, which is immeasurable, but because it removes a class of accident where a $ in the text becomes a variable.

Two operators worth having reflexively: ?? returns the right-hand side when the left is null or not set, without a warning; ?: tests falsiness and warns on undefined. So $_GET['page'] ?? 1 is safe, and it correctly keeps 0 and "" as real values, which ?: would throw away. 

<?php declare(strict_types=1);

$config = ['retries' => 0, 'label' => ''];

var_dump($config['retries'] ?? 3);     // int(0)  — 0 is a real value
var_dump($config['retries'] ?: 3);     // int(3)  — 0 is falsy, silently replaced
var_dump($config['missing'] ?? 3);     // int(3)  — no warning
// var_dump($config['missing'] ?: 3);  // int(3), plus a warning

$user = null;
var_dump($user?->name);                // NULL — nullsafe, no fatal error

The array is one data structure doing five jobs

🧒 Simple

Other languages give you a list and a dictionary as separate things. PHP gives you one box that does both. It remembers the order you put things in, and it lets you label them.

🎓 Professional

A PHP array is an ordered hash map. That one sentence explains why it can be a list, a dictionary, a stack and a queue; why insertion order is preserved; why array_values() exists; and why PHP 8.1 needed to add array_is_list() — "is this actually a list?" is a real question you have to ask it.

The operator to get right: + keeps the left operand's value on a key collision, while array_merge() keeps the right. Also, array_merge() renumbers integer keys and + does not.

⚠ Trap

Arrays are assigned by value (with copy-on-write), objects by handle. So passing an array to a function and modifying it inside changes nothing outside, while doing the same to an object does. Mixing these up produces a bug that looks like the function "did not run". 

<?php declare(strict_types=1);

$a = ['x' => 1, 'y' => 2];
$b = ['y' => 9, 'z' => 3];

print_r($a + $b);              // y stays 2  — left wins
print_r(array_merge($a, $b));  // y becomes 9 — right wins

var_dump(array_is_list([1, 2, 3]));        // true
var_dump(array_is_list([1 => 'a', 0 => 'b'])); // false — keys out of order

// by value vs by handle
function touchArray(array $in): void  { $in[] = 'added'; }
function touchObject(stdClass $o): void { $o->added = true; }

$arr = []; touchArray($arr); var_dump($arr);   // still empty
$obj = new stdClass; touchObject($obj); var_dump($obj); // has ->added
Golden rules
  • === unless you have a reason. Loose comparison is a decision, not a default.
  • declare(strict_types=1) in every file. It is per-file and per-call-site; one central declaration does not exist.
  • PHP 8 casts the number to string when comparing against a non-numeric string. 0 == "foo" is now false.
  • ?? for "not set", ?: for "falsy". They are not interchangeable, and 0 is where they differ.
  • An array is an ordered hash map. Everything surprising about it follows from that.
  • + keeps left, array_merge() keeps right — and merge renumbers integer keys.
  • Arrays by value, objects by handle.

"Che differenza c'è tra == e ===?"

Do not stop at "one checks the type". Add the PHP 8 change and one consequence: "== converte i tipi prima di confrontare, === richiede stesso tipo e stesso valore. In PHP 8 il confronto tra un numero e una stringa non numerica è cambiato: ora viene convertito il numero a stringa, quindi 0 == "foo" è diventato false. Per gli oggetti, == significa stessa classe e proprietà uguali, === significa la stessa identica istanza."
