The Angular/TypeScript front end you will touch

The Modena advert wants Java behind an Angular front end, and asks for a year of it. This chapter is enough Angular to be useful in a full-stack team, to review a pull request, and to debug the boundary between the two — without pretending to be a frontend developer.

From the advert

“Minimo due anni di esperienza nello sviluppo software, di cui uno con il framework Angular/TypeScript”, from the Modena software house.

The shape of an Angular application

🧒 Simple

An Angular app is a tree of components, each with a template and a class. Shared logic and anything that talks to the server lives in a service, which components ask for — the same dependency injection idea as Spring.

🎓 Professional

Components own view state; services own data access and shared logic and are usually singletons provided at the root injector. If you know Spring, Angular’s DI will feel familiar — it is constructor injection with a hierarchical injector.

Two things have changed recently and are worth knowing so you do not sound five years out of date: standalone components have largely replaced NgModules, and signals are the new reactive primitive alongside RxJS. A codebase asking for “a year of Angular” is most likely a mix of both eras.

RxJS, and the subscription you forgot

🧒 Simple

HTTP calls in Angular return an Observable: a stream of values you subscribe to. Nothing happens until something subscribes.

And if you subscribe and never unsubscribe, the component leaks.

🎓 Professional

Observables are lazy and, for HTTP, cold: no request is sent until subscription, which is the first thing that confuses a backend developer (“why did my call not happen?”). Prefer the async pipe in templates, which subscribes and unsubscribes with the component’s lifetime and removes the whole class of leak.

The operators you will actually meet: map, filter, switchMap (cancel the previous inner request — the correct choice for a typeahead), catchError, and debounceTime. Manual subscribe() in a component without takeUntilDestroyed is the most common review comment in Angular code, and now you can make it.

⚠ Trap

switchMap versus mergeMap matters for correctness, not style. On a search box, mergeMap lets an earlier, slower response arrive after a later one and overwrite it — so the user sees results for a query they have already changed. switchMap cancels the previous one.

The boundary, which is your half

🧒 Simple

The place a backend developer actually adds value is where the two sides meet: the shape of the JSON, the error responses, CORS, and dates.

🎓 Professional

CORS is the classic. The browser sends a preflight OPTIONS for anything non-simple, and it must succeed without authentication — which is why a misconfigured Spring Security chain (chapter 20) produces “CORS error” in the console when the real problem is a 401 on the preflight. Configure CORS in Spring, not by adding headers by hand.

Then: keep the error body one shape (chapter 18) so the front end has one error path; send ISO-8601 dates and let the client format them, since only the browser knows the user’s timezone; and generate the TypeScript client from OpenAPI (chapter 21) so a renamed field breaks the build rather than the page.

Golden rules
  • Components own view state, services own data. DI works like Spring’s.
  • Standalone components and signals — know them, or you sound out of date.
  • Observables are lazy. No subscription, no request.
  • Prefer the async pipe over manual subscribe-and-leak.
  • switchMap for typeaheads. mergeMap lets stale results win.
  • A CORS error is often a 401 on the preflight. Configure CORS in Spring.

“Ha esperienza full-stack? Quanto Angular sa?”

Be exact about the boundary rather than vague about the whole: “Il mio centro di gravità è il backend, ma in Angular mi muovo: componenti, servizi, RxJS per le chiamate HTTP, e so perché si usa switchMap invece di mergeMap su una ricerca. Dove aggiungo davvero valore è sul confine: forma del JSON, una sola forma per gli errori, date in ISO-8601, e il client TypeScript generato da OpenAPI, così se rinomino un campo si rompe la build e non la pagina. Non mi spaccio per frontendista, ma non sono un collo di bottiglia.”
