Pipelines, and migrations in them

Build once, promote the same artefact, and keep schema changes out of application start-up. The migration race is a defect the C# academy’s blueprint documents from its own history — two instances starting together both run migrations, and only one wins.

From the advert

Not in any advert. Implied by every one that mentions Kubernetes or a team: somebody has to decide how code reaches production, and being able to describe that is a mid-level expectation.

Build once, promote the same artefact

🧒 Simple

Build the application once, then move that exact artefact through test, staging and production. Never rebuild per environment.

If you rebuild, the thing you tested is not the thing you shipped.

🎓 Professional

One immutable artefact — a container image with a digest — promoted across environments, with configuration injected per environment (chapter 13). Rebuilding per environment reintroduces the possibility that a dependency resolved differently, which is precisely the class of problem the pipeline exists to eliminate.

Tag images with something traceable: the git SHA, not latest. latest is not a version, it makes rollback ambiguous, and it defeats the image caching you set up in chapter 41.

The stages worth having

🧒 Simple

Compile, run the fast tests, run the slower integration tests, scan for known vulnerabilities, build the image, deploy. Fail early and cheaply.

🎓 Professional

Order by cost: unit tests before integration tests (chapter 39’s *IT split pays for itself here), static analysis and dependency scanning before the image build, deployment last. A pipeline that takes forty minutes to tell you about a typo is a pipeline people route around.

Add a dependency vulnerability scan — the OWASP dependency-check plugin, or the registry’s own scanning — and treat the results as a triage list rather than a gate that blocks everything. Being able to say “we scan, and we have a policy for what blocks a release” is a much better answer than either extreme.

Migrations belong in the pipeline

🧒 Simple

If migrations run when the application starts, and you start three copies at once, all three try to migrate the same database at the same time.

🎓 Professional

Run migrations as a distinct, gated step before the new version is deployed — a Kubernetes Job, or a pipeline stage. Two reasons: instances starting together race, and the runtime database account would otherwise need schema-altering rights it should never hold (chapter 29).

Flyway does take a lock, so a race usually resolves rather than corrupting anything — but it turns a deploy into a sequence of instances waiting on each other, and it fails in genuinely confusing ways when a migration is slow. Combined with expand-and-contract, running migrations first means the old version keeps working throughout the rollout, which is what makes a rollback safe.

⚠ Trap

A rollback rolls the code back; it does not roll the schema back. If the migration dropped a column the previous version reads, rollback is impossible and you are now fixing forward under pressure. That is the whole argument for expand-and-contract, and it is worth stating in exactly those terms.

Golden rules
  • Build once, promote the artefact. Rebuilding per environment tests something else.
  • Tag with the git SHA. latest is not a version.
  • Order stages by cost. Slow feedback gets routed around.
  • Migrations are a gated pipeline step, not application start-up.
  • The runtime account should not hold DDL rights.
  • Rollback reverses code, not schema. Expand and contract, always.

“Dove eseguite le migrazioni del database nel vostro processo di deploy?”

“Come step separato della pipeline, prima del deploy della nuova versione, non all’avvio dell’applicazione. Due motivi: con più repliche che partono insieme si crea una race, e l’utenza con cui gira l’applicazione non dovrebbe avere permessi di DDL. E le migrazioni le scrivo expand-and-contract, perché il rollback riporta indietro il codice ma non lo schema: se la migrazione ha eliminato una colonna che la versione precedente legge, il rollback non è più possibile e ti tocca fixare in avanti sotto pressione.”
