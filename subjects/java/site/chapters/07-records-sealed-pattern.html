Records, sealed types and pattern matching

The Java 17 feature set, which exists to do one thing: let you model data as data, and let the compiler check that you have handled every case. On a code test for a Java 17 job, using these is the difference between writing modern Java and writing Java 8 that compiles.

From the advert

Not in any advert by name — but one advert asks for “Java 17 (Spring Boot)”, and this is what that version is for. A thirty-line DTO on a Java 17 code test answers a question nobody asked aloud.

Records

🧒 Simple

A record is a class whose whole job is to hold a few values. You declare the values; Java writes the constructor, the accessors, equals, hashCode and toString.

🎓 Professional

A record is a transparent carrier for its components: implicitly final, fields are final, and equals is component-wise by construction — which means it is correct without you maintaining it, and correct is the operative word given chapter 03.

Use the compact constructor for validation and normalisation. Records can implement interfaces and have extra methods; they cannot extend a class. In Spring they are excellent as request/response DTOs and as @ConfigurationProperties targets, which is where they replaced Lombok for most teams.

⚠ Trap

A record is shallowly immutable. record Basket(List<Item> items) hands out the same mutable list every caller can modify. Copy in the compact constructor — items = List.copyOf(items) — or the immutability is decorative.

Sealed types

🧒 Simple

sealed lets a type say exactly which types are allowed to extend it. The list is closed, and the compiler knows it.

That means the compiler can tell you when you have forgotten a case.

🎓 Professional

sealed interface Payment permits Card, Transfer, Cash makes the hierarchy closed and known at compile time. Combined with a switch, the compiler performs exhaustiveness checking: add a fourth implementation and every switch that does not handle it fails to compile.

That is the real value, and the argument to make in an interview: an enum models a closed set of constants, a sealed interface models a closed set of shapes, each with its own fields. It turns “remember to update the switch” from a code-review convention into a compiler error.

Pattern matching

🧒 Simple

Instead of checking a type and then casting it, you do both at once and get a named variable that is already the right type.

🎓 Professional

if (o instanceof Point p) binds p in the scope where the test succeeded. Java 21 extends this to switch with record patterns, so you can destructure in the case label itself and let the compiler verify exhaustiveness over a sealed hierarchy.

Taken together with records and sealed types, this is Java catching up with algebraic data types — and the practical payoff is that a state machine or a result type stops being a tangle of nullable fields and becomes something the compiler polices.

Try it. Run it, then add a fourth Payment implementation without touching the switch. The compile error is the entire point of the feature.

sealed interface Payment permits Card, Transfer, Cash {}
record Card(String pan, int instalments) implements Payment {}
record Transfer(String iban) implements Payment {}
record Cash() implements Payment {}

public class Fees {
    static double fee(Payment p) {
        return switch (p) {                       // no default: exhaustive over the sealed set
            case Card c when c.instalments() > 1 -> 2.50;
            case Card c                          -> 0.90;
            case Transfer t                      -> 0.00;
            case Cash ignored                    -> 0.00;
        };
    }
    public static void main(String[] args) {
        System.out.println(fee(new Card("4000", 3)));
    }
}
Golden rules
  • A record is a transparent data carrier with correct equals by construction.
  • Validate in the compact constructor, and copy mutable components while you are there.
  • Sealed + switch gives exhaustiveness checking. That is the reason to use it.
  • Enum = closed set of constants; sealed interface = closed set of shapes.
  • On a Java 17 job, write Java 17. The DTO is where it shows first.

“Cosa le dà un record rispetto a una classe normale?”

Do not stop at “less boilerplate”, which is the answer everyone gives: “Meno codice, sì, ma soprattutto correttezza per costruzione: equals e hashCode sono generati sui componenti, quindi non posso dimenticarmi di aggiornarli quando aggiungo un campo — che è esattamente il bug silenzioso delle collezioni hash. E il record è immutabile, quindi è una chiave sicura e si può condividere tra thread.” Then add the shallow-immutability caveat yourself; volunteering the limitation of your own answer is what a senior candidate sounds like.
