Lambdas, streams and Optional

The Java 8 features every advert assumes and few candidates can discuss precisely. What a lambda actually compiles to, why a stream does nothing until you ask it for something, and the Optional rules that separate people who use it from people who have read about it.

From the advert

“Solida esperienza con Java 8+”. In practice this is tested by handing you a loop and asking you to rewrite it, or by asking what map and flatMap differ in.

Lambdas and functional interfaces

🧒 Simple

A lambda is a small function written inline, without giving it a name or a class. Java lets you pass one anywhere an interface with exactly one method is expected.

🎓 Professional

A lambda is not an object literal for a new anonymous class — it compiles to an invokedynamic instruction resolved at first use by LambdaMetafactory, which typically avoids allocating a class per lambda. That is why lambdas are cheaper than the anonymous inner classes they replaced.

The target type must be a functional interface: one abstract method. Function, Predicate, Consumer, Supplier and BiFunction cover most needs. One behavioural difference worth knowing: inside a lambda, this refers to the enclosing instance, whereas in an anonymous class it refers to the anonymous instance.

Streams: lazy, and consumed once

🧒 Simple

A stream is a recipe, not a dish. filter and map only write down what to do. Nothing happens until you finish with something that wants an answer — collect, count, findFirst.

And a stream can only be used once. Reading it a second time throws.

🎓 Professional

Intermediate operations are lazy and return a new stream; a terminal operation triggers evaluation and consumes the source. Elements are pulled through the whole pipeline one at a time rather than materialising an intermediate collection per stage, which is what makes short-circuiting operations like findFirst and anyMatch cheap on a long source.

map transforms one element into one element. flatMap transforms one element into a stream and then flattens — the operation you want when each order has a list of lines and you want all the lines. That distinction is the single most asked stream question.

⚠ Trap

parallelStream() is not a free speed-up. It uses the common ForkJoinPool, so one slow parallel stream can starve every other one in the JVM — and inside a web request, where you already have a thread per request, it usually makes throughput worse. Use it for large, CPU-bound, side-effect-free work, and measure.

Try it. Run it, then swap flatMap for map and read the compiler error — it tells you exactly what shape you ended up with.

import java.util.*;
import java.util.stream.*;

record Line(String sku, int qty) {}
record Order(String id, List<Line> lines) {}

public class Streams {
    public static void main(String[] args) {
        var orders = List.of(
            new Order("A", List.of(new Line("x", 2), new Line("y", 1))),
            new Order("B", List.of(new Line("x", 5))));

        // every line across every order
        List<Line> all = orders.stream()
                               .flatMap(o -> o.lines().stream())   // map would give Stream<Stream<Line>>
                               .toList();

        Map<String, Integer> perSku = all.stream()
            .collect(Collectors.groupingBy(Line::sku, Collectors.summingInt(Line::qty)));

        System.out.println(perSku);   // {x=7, y=1}
    }
}

Optional, used properly

🧒 Simple

Optional is a box that either holds a value or is empty. It exists so a method can say “there may be nothing here” in its signature instead of quietly returning null.

🎓 Professional

It was designed as a return type, and the rules follow from that: do not use it for fields (it is not serialisable and adds an allocation per access), do not use it for parameters (callers then have to wrap), and never return null from a method returning Optional, which is a special kind of cruelty.

Prefer map, filter and orElseGet over isPresent()/get(), which is just a null check with more typing. Note orElse evaluates its argument eagerly even when the value is present — if that argument is a database call, use orElseGet.

Golden rules
  • A lambda needs a functional interface — exactly one abstract method.
  • Streams are lazy and single-use. Nothing runs until a terminal operation.
  • flatMap when each element yields many; map when it yields one.
  • parallelStream() shares the common pool. Rarely right inside a web request.
  • Optional is a return type. Not a field, not a parameter, never null.
  • orElseGet, not orElse, when the fallback costs anything.

“Che differenza c’è tra map e flatMap?”

Answer with shapes, then an example: “map trasforma un elemento in un elemento, quindi da uno Stream<Order> ottengo uno Stream<Qualcosa>. flatMap trasforma un elemento in uno stream e poi appiattisce: se ogni ordine ha una lista di righe, con map avrei uno stream di stream, con flatMap ottengo direttamente tutte le righe.” If you have time, add that streams are lazy — it is the follow-up they were going to ask anyway.
