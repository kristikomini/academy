Modbus RTU

Published in 1979 and still the most likely thing on the wire between a proprietary board and the PLC beside it. Deliberately simple, which means the difficulties are all in the details: the silence that delimits a frame, four address spaces, and an off-by-one that has cost everyone a day.

From the advert

Not named in this advert — it says “protocolli di comunicazione seriale” and leaves it there. But between a board and a PLC in an Italian machine-building company, Modbus RTU over RS-485 is the single most probable answer, and it appears by name across the regional listings collected alongside this one.

LogiFlow chapter 32b covers the register map from the PC side, where a library hides all of this. Here you are the device, and none of it is hidden.

One master, and four address spaces

🧒 Simple

Modbus is a conversation with a strict rule: only one device is allowed to start a sentence. It asks, one device answers, and then it asks again. Nobody ever speaks unprompted.

The things you can ask about are just numbered boxes. Some hold a single yes/no, others hold a 16-bit number. Some you may only read; others you may also write.

🎓 Professional

Strictly master/slave (the current specification says client/server). One master polls; slaves answer and never initiate. Each slave has an address 1–247; 0 is broadcast, which is write-only and unacknowledged.

Four data tables, and knowing them cold is the entry ticket:

TableSizeAccessRead withWrite with
Coils1 bitread/writeFC 01FC 05, 15
Discrete inputs1 bitread onlyFC 02—
Input registers16 bitread onlyFC 04—
Holding registers16 bitread/writeFC 03FC 06, 16

An RTU frame is: address (1 byte), function code (1), data (n), CRC-16 (2, little-endian — the only little-endian field in a protocol that is otherwise big-endian). Maximum PDU 253 bytes, so 256 on the wire.

On error the slave replies with the function code plus 0x80 and one exception byte: 01 illegal function, 02 illegal data address, 03 illegal data value, 04 slave device failure, 06 busy. Returning a correct exception instead of staying silent is the difference between a device that is debuggable and one that is not — silence is indistinguishable from a dead cable.

The 3.5-character silence

🧒 Simple

Modbus RTU has no start or end marker. Instead, a message is defined by quiet: if the line has been silent for a little while, the next byte starts a new message, and a gap in the middle of a message means the message is broken.

That makes it a protocol about timing, not just about bytes — which is why it is harder on an operating system than on a microcontroller.

🎓 Professional

Frames are delimited by idle time on the line:

  • t3.5 — silence of at least 3.5 character times marks end of frame.
  • t1.5 — a gap greater than 1.5 character times within a frame means the frame is incomplete and must be discarded.

A character is 11 bit-times (start + 8 data + parity + stop; with no parity, 2 stop bits are used to keep it at 11). At 9600 baud that makes t3.5 about 4 ms and t1.5 about 1.7 ms. Above 19200 baud the specification says to use fixed values — 1.750 ms and 0.750 ms — rather than scaling, because the character times get short enough that chasing them is pointless.

The clean implementation on STM32 does not measure this in software at all. Use UART idle-line detection plus DMA: the DMA fills a buffer, the IDLE interrupt fires when the line goes quiet, and you compute the received length from the remaining DMA count. One interrupt per frame, no per-byte work, and the framing is done by hardware (chapter 46, chapter 27).

On RS-485 there is a second timing job: the driver enable. Half duplex means you must assert DE before the first bit and release it after the last bit has physically left the shift register — that is the transmission complete flag, not the transmit-buffer-empty flag. Releasing on the wrong flag truncates the final character, and the symptom is an intermittent CRC error at the master (chapter 45).

⚠ Trap

Register 40001 is register 0 on the wire. This has cost every person who has ever touched Modbus at least one afternoon.

The old Modicon convention numbers entities from 1 with a leading digit for the table: 0xxxx coils, 1xxxx discrete inputs, 3xxxx input registers, 4xxxx holding registers. So documentation says “holding register 40001” and means address 0x0000 with function code 03. Holding register 40018 is address 17.

Different tools disagree about which convention they present. A PLC configuration screen may want 40018, your firmware sees 17, and a Python library wants 17 as well. When the value you read is consistently one register away from the value you expected, this is why — and the fix is to state the convention explicitly in your register map document, with one worked example of each, rather than to add a ±1 somewhere and move on (chapter 58).

The second off-by-one, from the same family: a 32-bit value occupies two consecutive registers, and the specification does not say in which order. Both orders exist in shipping products and both are called “Modbus”. Document yours.

Try it. No board and no PLC needed. This gives you a real Modbus slave on your PC and a master to poke it with, which is enough to learn the frame format properly.

# A slave and a master in Python, on loopback TCP first (same PDU, see ch. 53)
pip install pymodbus

# terminal 1 -- a slave with 100 holding registers
python -m pymodbus.server --host 127.0.0.1 --port 5020 --store sequential

# terminal 2
python - <<'EOF'
from pymodbus.client import ModbusTcpClient
c = ModbusTcpClient('127.0.0.1', port=5020)
c.connect()
c.write_register(17, 1234)              # <- address 17 ...
print(c.read_holding_registers(17, 1).registers)
# ... which your PLC's screen will call register 40018. Same register.
EOF

# Now compute a CRC by hand and check it against a known-good frame.
# Read holding register 0, one register, from slave 1:
#     01 03 00 00 00 01 84 0A
#     ^^ addr
#        ^^ FC03
#           ^^^^^ start address 0
#                 ^^^^^ quantity 1
#                       ^^^^^ CRC-16, LITTLE-endian (0x0A84 sent low byte first)
python - <<'EOF'
def crc16(d):
    c = 0xFFFF
    for b in d:
        c ^= b
        for _ in range(8):
            c = (c >> 1) ^ 0xA001 if c & 1 else c >> 1
    return c
v = crc16(bytes([0x01,0x03,0x00,0x00,0x00,0x01]))
print(hex(v), '-> on the wire:', hex(v & 0xFF), hex(v >> 8))
EOF
Golden rules
  • One master, and slaves never speak unprompted. Addresses 1–247; 0 is unacknowledged broadcast.
  • Four tables: coils and discrete inputs are bits, input and holding registers are 16 bits; only coils and holding registers are writable.
  • A frame is delimited by silence — 3.5 character times — not by a start or end byte.
  • The CRC is the only little-endian field in an otherwise big-endian protocol.
  • Answer errors with function code + 0x80 and an exception byte. Silence is indistinguishable from a dead cable.
  • 40001 is address 0. State the convention in your register map, with a worked example.
  • Nothing specifies the word order of a 32-bit value. Both orders ship. Document yours.
  • On RS-485, release the driver enable on transmission-complete, never on transmit-buffer-empty.

“Ha mai implementato Modbus? Come gestisce il framing?”

“Modbus RTU non ha un carattere di inizio né di fine: il frame lo delimita il silenzio sulla linea, 3,5 tempi-carattere. Quindi non lo gestisco contando i byte a mano — su STM32 uso il rilevamento di linea idle della UART insieme al DMA: il DMA riempie il buffer, l’interrupt IDLE scatta quando la linea tace, e la lunghezza la ricavo dal contatore residuo del DMA. Un interrupt per frame invece di uno per byte. Su RS-485 c’è la seconda parte del lavoro, il driver enable: va rilasciato sul flag di trasmissione completata, non su quello di buffer vuoto, altrimenti tronco l’ultimo carattere e il master vede errori di CRC intermittenti. Poi rispondo sempre con l’eccezione — function code più 0x80 — invece di stare zitto, perché il silenzio è indistinguibile da un cavo staccato. E la cosa che scrivo sempre nel documento della mappa registri: se dico 40018 intendo indirizzo 17, e per i valori a 32 bit specifico l’ordine delle due word, perché lo standard non lo dice e in giro ci sono tutti e due.”
